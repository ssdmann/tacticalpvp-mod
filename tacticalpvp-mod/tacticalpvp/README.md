# Tactical PvP / Sector Control — Мод для Minecraft Forge 1.20.1

Тактичний PvP режим із лінійним захопленням точок ("перетягування канату"),
динамічною системою відродження, класами/кітами та повним циклом матчу.

> ⚠️ **Важливо про стан проєкту**: це повний вихідний код (Java + конфіги +
> локалізація), написаний згідно ТЗ. Через мережеві обмеження середовища,
> в якому код писався, **компіляцію через Gradle/ForgeGradle перевірити не
> вдалося** (немає доступу до `files.minecraftforge.net` та Maven Forge).
> Перед використанням на реальному сервері рекомендується зібрати проєкт
> локально (`./gradlew build`) і виправити можливі дрібні неточності API
> (назви методів між патч-версіями Forge 1.20.1 іноді відрізняються).

---

## 1. Встановлення

1. Розпакуйте архів у папку проєкту Forge MDK 1.20.1 (або використайте
   наданий `build.gradle` як основу нового проєкту).
2. Скопіюйте вміст папки `config/` у корінь вашого сервера (поруч з `mods/`),
   щоб кіт-конфігурації підхопились автоматично.
3. Зберіть мод: `./gradlew build`, jar-файл з'явиться у `build/libs/`.
4. Покладіть jar у `mods/` на сервері Forge 1.20.1.

## 2. Команди адміністратора

### 2.1 Точки захоплення (`/point`)

| Команда | Опис |
|---|---|
| `/point create <index> <neutral/red/blue> <length> <width>` | Створює точку захоплення. Центром зони стає позиція адміна у момент виконання команди. Висота зони — нескінченна. |
| `/point create spawnpoint <attached_index> <red/blue>` | Прив'язує точку відродження вказаної команди до контрольної точки. Точка сама по собі більше НЕ є спавном — лише "ключем". Радіус розкидання при відродженні — 7 блоків. |

**Логіка фронту**: спавн команди на точці `N` активний, доки точка `N-1`
(сусідня, ближча до бази) не захоплена ворогом. Якщо `N-1` захоплено ворогом —
спавн вашої команди на `N` вимикається, і гравці автоматично відроджуються на
найближчій активній точці позаду.

### 2.2 Зони вибору команди (`/teamzone`)

```
/teamzone create <red/blue> <length> <width>
```

Центр зони — позиція адміна. Гравець, що заходить у зону, отримує великий
напис "СИНІ" або "ЧЕРВОНІ" і призначається у відповідну команду. Зміна
команди дозволена **лише до старту матчу** (до виконання `/match teleporteams`
або старту передматчевого відліку).

### 2.3 Матч (`/match`)

| Команда | Опис |
|---|---|
| `/match init` | Повністю скидає стан матчу, вмикає `keepInventory`, очищує команди/класи. |
| `/match setgenerallobby` | Встановлює загальне лобі (позиція адміна). Час перебування тут необмежений. |
| `/match setlobby <red/blue>` | Встановлює лобі очікування конкретної команди. |
| `/match lobbytimer <секунди>` | Скільки часу гравець чекає у лобі команди після смерті, перш ніж телепортуватись на фронтовий спавн. |
| `/match prestarttimer <хвилини 1-20>` | Тривалість передматчевого відліку. |
| `/match teleporteams` | Телепортує гравців у лобі їх команд, видає всім Око вибору класу, **запускає** передматчевий відлік. |
| `/match duration <хвилини>` | Тривалість самого матчу у реальних хвилинах. |
| `/match scorelimit <число>` | Ліміт рахунку вбивств для перемоги. |
| `/match start` | Ручний примусовий запуск матчу (без відліку) — резервний варіант. |
| `/match stop` | Аварійна зупинка матчу, повернення фази у LOBBY. |
| `/match pause` / `/match resume` | Пауза/відновлення таймера й рахунку матчу. |

**Логіка відліку**: кожні 20 секунд — повідомлення в загальний чат.
Останні 10 секунд — щосекунди. Фінал: `5, 4, 3, 2, 1, Старт!`.

**Перемога**: велике повідомлення на весь екран ("СИНІ ПЕРЕМОГЛИ!" /
"ЧЕРВОНІ ПЕРЕМОГЛИ!"), потім відлік повернення у загальне лобі. Після
відліку — повне очищення інвентарів і телепорт у загальне лобі.

### 2.4 В'язниця (`/punishpoint`, `/punish`)

| Команда | Опис |
|---|---|
| `/punishpoint set` | Встановлює координати в'язниці (позиція адміна). |
| `/punish <гравець> <хвилини>` | Телепортує гравця у в'язницю, очищує інвентар, переводить у Adventure-режим на вказаний час. |

Після завершення терміну гравець автоматично повертається у Survival-режим і
телепортується у лобі очікування своєї команди. Таймери зберігаються у World
Save Data — **переживають рестарт сервера**.

### 2.5 Кіти та класи (`/kit`)

```
/kit give <гравець> <blue/red> <назва_класу>
```

Назви класів у конфігах: `assault`, `grenadier`, `drone_pilot`, `engineer`.
Ця команда видає кіт **в обхід** GUI та лімітів класу (адмінський форс-режим).

Звичайний гравець обирає клас через ПКМ по "Оку вибору класу", яке видається
автоматично всім гравцям під час `/match teleporteams`. Вибір:
- **Штурмовик (Assault)** — ліміт 50% команди
- **Гранатометник (Grenadier)** — ліміт 20% команди
- **Пілот дрону (Drone Pilot)** — ліміт 10% команди
- **Інженер (Engineer)** — ліміт 20% команди

Якщо ліміт класу вичерпано — вибір блокується, гравцю приходить попередження,
і він повинен обрати інший клас із вільними слотами.

## 3. Конфігурація кітів (JSON)

Файли лежать у `config/tacticalpvp/kits/<red|blue>/<клас>.json`.
**Команди повністю ізольовані** — Red і Blue мають окремі файли, зміни в
одному ніяк не впливають на інший.

### 3.1 Структура файлу

```json
{
  "percentLimit": 50,
  "items": [
    { "item": "minecraft:iron_chestplate", "count": 1 },
    { "type": "random_weapon", "options": [ ... ] }
  ]
}
```

- `percentLimit` — відсоток гравців команди, які можуть обрати цей клас
  одночасно (рахується від поточної чисельності команди, мінімум 1 слот
  гарантовано завжди).
- `items` — список предметів кіта. Кожен елемент може бути:
  - **звичайним предметом**: `{ "item": "<registry_id>", "count": <число> }`
  - **рандомізованою зброєю**: блок `"type": "random_weapon"` з масивом
    `options`.

### 3.2 Підказки по рандомізації зброї

```json
{
  "type": "random_weapon",
  "options": [
    { "item": "tacticalpvp:rifle_ak", "weight": 50, "count": 1, "ammoItem": "tacticalpvp:ammo_762", "ammoCount": 90 },
    { "item": "tacticalpvp:rifle_m4", "weight": 30, "count": 1, "ammoItem": "tacticalpvp:ammo_556", "ammoCount": 90 },
    { "item": "tacticalpvp:shotgun",  "weight": 20, "count": 1, "ammoItem": "tacticalpvp:ammo_12ga", "ammoCount": 40 }
  ]
}
```

- Гравець отримає **рівно ОДНУ** зброю зі списку `options`.
- `weight` — відносна вага. Ваги **не обов'язково** мають сумарно давати 100:
  мод нормалізує їх автоматично (наприклад, `50/30/20` рівнозначно `5/3/2`).
- `ammoItem` + `ammoCount` — набій, що видається **разом** з обраною зброєю.
  Це поле опціональне — якщо зброя не потребує набоїв, просто не вказуйте
  `ammoItem`.
- Кожна `random_weapon` секція — це один незалежний "розіграш". Можна додати
  декілька таких блоків в один кіт (наприклад окремо для основної зброї і
  окремо для гранат).
- Щоб швидко перевірити конфіг на коректність — відкрийте файл будь-яким
  валідатором JSON (наприклад https://jsonlint.com) перед заливкою на сервер.

### 3.3 Перезавантаження конфігів

Наразі конфіги кітів завантажуються при першому зверненні до них (лениво,
кешуються). Для примусового оновлення після редагування файлів — перезапустіть
сервер, або викличте `KitConfigLoader.loadAll()` через власну адмін-команду,
якщо потрібно "гаряче" оновлення без рестарту.

## 4. HUD та інтерфейс

- **Азимутальний компас** — горизонтальна стрічка у самому верху екрана,
  показує N/E/S/W і градуси, плавно рухається за поворотом камери.
- **Рахунок і таймер матчу** — зсунуті трохи нижче компаса, щоб не
  перекриватись.
- **Індикатор захоплення** — ненав'язливий напис в зоні Action Bar
  (наприклад "Захоплення точки 2: 45%"), видимий лише гравцям, що фізично
  знаходяться всередині зони точки в момент захоплення.
- **Візуали точок** — контур меж малюється кольоровими частками: сірий
  (нейтральна), синій (команда Blue), червоний (команда Red).
- **Звук захоплення** — `minecraft:entity.player.levelup`, програється
  **лише** гравцям, що фізично стоять всередині точки у момент її захоплення.

## 5. Особливості логіки

- **Friendly Fire**: навіть якщо гравця вбив союзник, очко рахунку йде
  **ворожій** команді.
- **keepInventory** вмикається глобально командою `/match init` — тому кіт
  видається класу **один раз**, при виборі, а не при кожному відродженні.
- **Тривалості у реальному часі**: `/match duration`, `/match prestarttimer`,
  `/match lobbytimer` — усі приймають хвилини/секунди реального часу, а не
  тіки. Конвертація в тіки (1 сек = 20 тіків) відбувається автоматично
  всередині мода.
- **Персистентність**: усі точки, зони, лобі, в'язниця, активні покарання та
  стан матчу зберігаються у World Save Data (`world/data/tacticalpvp_data.dat`)
  і переживають рестарт сервера.

## 6. Структура вихідного коду

```
com.tacticalpvp.mod
├── TacticalPvpMod.java          // головний клас, реєстрація всього
├── commands/                    // /point, /match, /teamzone, /punish, /kit
├── points/                      // CapturePoint, TeamSpawnPoint, SpawnLogic, тіковий обробник
├── match/                       // MatchState, TeamZone, MatchEventHandler (фази/смерть/зони)
├── punish/                      // PunishEntry, PunishTickHandler
├── kits/                        // PlayerClass, KitEntry, KitConfigLoader, ClassLimitManager, KitDispenser
├── item/                        // ModItems, EnderEyeKitItem
├── menu/                        // ClassSelectionMenu (сервер), ClassSelectionScreen (клієнт)
├── network/                     // NetworkHandler + пакети (вибір класу, HUD-синхронізація)
├── hud/                         // CompassOverlay, MatchHudOverlay, ClientHudState
└── util/                        // Team, PlayerTeamTracker, TacticalWorldData (SavedData)
```

## 7. Відомі спрощення / TODO для продакшену

- Предмети зброї у прикладах конфігів (`tacticalpvp:rifle_ak` тощо) — це
  **приклади ID**, реальні предмети зброї в цьому пакеті коду не реалізовані
  (мод не включає власну систему стрільби/балістики). Замініть на ID
  реальних предметів з вашого серверного модпаку (наприклад з інших модів
  на зброю), або на ванільні предмети як у готових конфігах `red/`, `blue/`.
- Система крафтового "supply crate" зі смарт-таймерами рестоку згадана у
  вимогах до персистентності, але детальна механіка (вигляд блоку, вміст,
  інтервали) не була деталізована у технічному завданні — рекомендується
  окремо уточнити специфікацію цього блоку перед реалізацією.
- Рекомендується протестувати повний цикл матчу на тестовому сервері перед
  використанням у бойових умовах.
